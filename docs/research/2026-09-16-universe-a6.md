## 3. Cost options (Haiku 4.5 Batch, $0.5/M in, $2.5/M out after the discount)

Calibration used `count_tokens` on 20 random requests:
- Mean input is 1,124 tokens at 1.321 chars/token.

- The system prompt is only 206 chars, so prompt caching would not reduce this.

Output is estimated at 200 tokens (the guard default); the live measurement is about 150.

| option | requests | guard estimate (cpt 1.0, 200 out) | calibrated (cpt 1.20, 200 out) | calibrated, 150 out |
|---|---|---|---|---|
| (a) full | 331,308 | $412.52 | $371.26 | $329.84 |
| (b) last 40 days full + 10k stratified rest | 109,812 | $136.73 | $123.05 | $109.33 |
| (b') 5k stratified last 40 days + 5k stratified rest | 10,000 | $12.45 | $11.20 | $9.95 |
| (c) 10k stratified (month, sector, session) | 10,000 | $12.45 | $11.21 | $9.96 |

The brief asked for (b) as "last 40 days + rest up to 10k". That cannot be done, because the last 40 days alone hold 99.8k pairs. (b) is therefore priced as the full 40 days plus 10k, and (b') is a 10k split between recent and older days. `judge_batch` has no recency-weighted mode today, so (b) and (b') would need a small CLI addition (or two runs with pre-filtered pair files).

## 4. Decision

(a) costs about $330-$413, above the $60 auto-submit cap, so it was not submitted. The controller then chose (c); see section 5.
