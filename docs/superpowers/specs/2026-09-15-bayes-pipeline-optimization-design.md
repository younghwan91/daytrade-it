# 뉴스 매매 파이프라인 베이즈 최적화 (프롬프트 → 신호 → 진입 → 청산) — 설계

작성 2026-09-15. 상태: 설계 합의(사용자 "바로 시작해"), 구현 계획 작성 중.

## 왜

- 09-15 실거래 결과(비공개). 그날 신호 35건을 전부 샀어도 평균 −0.63%였다. 문제는 한도·순서가 아니라 **신호 자체**다.
- 복기에서 나온 가설: 장중 기사 진입(실거래 사례, 종목명 비공개), 이미 떨어지던 종목(기사 전 −2% 이하 13건 평균 −0.84%), 섹터 흐름(제약 +7.3% 날 제약 진입 0, 약세 섹터 금융·통신에 신호 집중).
- 지금까지 규칙은 거래일 6일로 골랐고, 각 평가가 운영과 조금씩 다른 조건(종가 라벨, 진입 지연 가정, 규칙 재구현)이었다.
- 머신러닝은 표본 대비 위험하다(기존 연구에서 릿지·GBM이 단순 규칙보다 못함). 사람이 정의한 규칙 후보를 **베이즈 최적화로 탐색하고, 베이즈 모형으로 판정**한다. 베이즈 판정은 작은 표본에서 효과 크기를 0 쪽으로 당겨 과신을 막는다.

## 제1원칙: 백테스트 = 실매매 (운영 동일성)

사용자 지시(2026-09-15): **테스트와 매매는 무조건 같은 조건이어야 하고, 실매매에서 가능한 것만 테스트한다.**

규칙을 복사해 다시 짜지 않는다. **운영 코드를 그대로 돌리는 리플레이 엔진**을 만든다.

- 판정: `AnthropicClient.score_article` 그대로, 같은 모델(Haiku 4.5), 같은 입력(`article.summary or article.content`, 종목명·시장·업종).
- 신호: `SignalGenerator`, `generate_no_chase_confirmation` 그대로.
- 주문·보유·청산: `AutoTrader`와 `execute_trade` 그대로. 바꾸는 것은 브로커(`SimBroker`, 분봉 기반), 시계(가짜 시계 주입), 판정 결과 캐시뿐이다.
- 한도: `TradingLimits` 그대로 (1주, 동시 5, 하루 10, 진입 09:00:30~14:30, TTL 5분, 15:00 청산·재시도, 노출 100만원, 추가매수 규칙).
- 비용: 매도세 0.20% + 수수료 편도 0.015%.

**운영에서 실시간으로 얻을 수 없는 정보를 쓰는 후보는 넣지 않는다.** 예: 섹터 흐름 필터는 운영 데몬이 장중에 섹터 수익률을 받을 수단(키움 업종 TR 등)을 먼저 확인하고, 없으면 후보에서 뺀다.

### 시뮬레이션이 운영과 달라지는 지점과 처리

| 항목 | 운영 | 리플레이 | 처리 |
|---|---|---|---|
| 기사 발견 시각 | 대시보드 폴링(약 3.5분) + 판정 | 09-14·15: 판정 아카이브의 실제 `judged_at` / 그 전: 발행 시각 + 지연 | 운영 판정 아카이브에서 발행→판정 지연 분포를 재고, 아카이브 없는 날은 그 분포의 중앙값을 쓴다. 날마다 분포 갱신 |
| 매수 체결 | 매도호가 지정가, 5분 TTL | 분봉 | 주문 시각 분봉의 시가를 매도호가·현재가로 본다. 이후 5분 안에 저가 ≤ 지정가인 첫 분에 체결. 상한가 잠김(고가 = 저가 = 상한가)은 매도호가 0 |
| 매도 체결 | 매수호가 −할인, 1분 재시도 | 분봉 | 주문 시각 분봉 시가를 매수호가로 보고, 지정가 ≤ 그 분 고가면 체결(가격 = max(지정가, 시가)) |
| DART 공시 게이트 | 10분마다 갱신된 `dart.db` | 같은 파일, 가짜 시계 | 신선도 검사는 끄고, `rcept_dt` ≤ 리플레이 날짜만 본다. 당일 공시의 접수 시각을 몰라 당일 공시는 전부 보이는 것으로 둔다(보수적: 진입을 더 막는 쪽) |
| 현금 | scalp-it과 공유 | 고정 110만원 | 노출 한도(100만원)가 먼저 걸리므로 운영과 같게 동작 |
| 사용자 보유(baseline) | 계좌 조회 | 빈 계좌 | 테스트 종목에 사용자 보유 없음으로 둔다 |

- 비교 대상: 운영 원장 `data/auto_trader/YYYY-MM-DD.jsonl`의 진입·추가매수·청산 종목과 수량, 데몬 로그의 스킵 사유.
- 통과: 진입·추가매수·청산 종목과 수량 **완전 일치**, 체결가 차이 종목당 ±0.5% 이내.

## 데이터: 운영이 실제로 받는 뉴스만

사용자 지시(2026-09-15): **실제로 우리가 다루는 뉴스만, 운영이 받는 포맷의 키와 종목으로.**

사용자 선택(2026-09-15): 데이터 범위 **B안(가장 공격적)**.

- **운영 데몬 가동일(09-14~):** 판정 아카이브 `data/news_judgments`만 쓴다. 운영이 실제로 받은 키·종목·판정·판정 시각이다. 같은 날 kr_quant에만 있는 기사는 운영이 못 본 것이라 **쓰지 않는다**("못 볼 건 학습하지 마").
- **데몬 가동 전(09-07~11):** kr_quant `news_articles` + `news_article_tickers`. 운영 키는 `uuid5(TOSS_NEWS_NAMESPACE, "toss:<hash>")`로 변환해 맞춘다. 운영 필터(종목 마스터, `stale_before`, 15:20 만료)를 통과한 쌍만. 판정은 운영 `score_article`로 새로 한다.
- 확인한 사실(09-14·15 대조): 겹치는 기사의 종목 태그는 65/65 일치. 하지만 kr_quant에는 운영이 본 기사의 약 25%만 있다. 따라서 09-07~11은 **그날 운영이 봤을 기사의 일부**이고, 동시 보유 한도 경쟁이 운영보다 약하다. 결과 문서에 날짜 출처별로 나눠 보고한다.
- 종목별 과거 뉴스 백필(`data/toss_history`)은 **쓰지 않는다.** 운영 피드에 없던 기사다.
- 규모(2026-09-15): 아카이브 2일 274쌍(매수 후보 157) + kr_quant 5일 약 280쌍. 하루 약 120쌍씩 늘어난다.

## 단계

### 1단계: 프롬프트

- 표본: 위 데이터 전부(약 400쌍 × 후보 수). 판정은 `data/eval/cache/`에 캐시.
- 후보: 운영 v2, v4(전문 입력판 — 대시보드 기사의 전문 아카이브 `data/toss_detail`이 있는 날만), 복기 가설을 반영한 신규 1~2종(예: 섹터·테마 필드 추가). **LLM에는 사실 추출만, 점수 계산은 코드**(기존 연구의 v3 실패 원칙).
- 호출: Haiku 4.5, Batch API. **예산 상한 $20** — 넘을 것 같으면 멈추고 보고.
- 평가 지표: 각 프롬프트로 만든 신호를 운영 정책(진입·청산 현행)으로 **리플레이한 하루 포트폴리오 손익**. 종가 대비 수익 같은 대리 지표로 고르지 않는다.

### 2단계: 신호·진입

선택된 프롬프트 고정, 청산은 현행 고정. 탐색 파라미터(모두 운영에서 계산 가능해야 함):
- 점수 하한, subject 허용(main/partial), persistence·material_type 제외 목록
- 세션별 진입 여부(장전 09:01 묶음 / 장중)
- 기사 전 움직임 상한(현행 +3%)과 **하한**(신규, 떨어지는 종목 제외)
- 배치 내 순위 기준(surprise, persistence, score)
- 섹터 흐름 필터 — 운영 데이터 소스 확인 시에만

### 3단계: 청산·추가매수

신호·진입 고정. VWAP 이탈(gap, 최소 이익), 손절(없음/2/3/5%), 청산 시각, 추가매수 조건.

### 4단계: 합동 확인

2·3단계 결과를 함께 켠 정책을 LODO로 확인하고, 전진 데이터로 넘긴다.

## 베이즈 방법

**탐색:** Optuna TPE, 학습일(빠진 날 제외)에서만. 운영 정책을 첫 시도로 넣는다. 단계당 시도 ≤ 300. 파라미터 수는 단계당 5개 이하로 묶는다(7일 표본).

**판정 모형:** 빠진 날 결과의 거래일별 포트폴리오 손익 차이 d_t = (후보 − 운영 정책).
- d_t ~ Student-t(ν, μ, σ), μ ~ Normal(0, 0.5%p) — 효과 크기를 0 쪽으로 수축시키는 사전.
- 구현: NumPyro 또는 PyMC(simnode), 수렴 진단(R-hat < 1.01).

**채택 조건 (모두 충족):**
1. P(μ > 0) ≥ 0.90
2. **손실 방지:** 하루 최대 손실(표본 최악일)과 손실 거래 비율이 운영 정책보다 나쁘지 않다. "벌지 못하면 잃지 않는다".
3. 7일 중 5일 이상 d_t ≥ 0
4. 전진 5거래일 이상에서 방향이 같을 것

탈락하면 운영 정책을 유지한다.
