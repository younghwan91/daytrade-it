# 뉴스 매매 파이프라인 베이즈 최적화 (프롬프트 → 신호 → 진입 → 청산) — 설계

작성 2026-09-15. 상태: 설계, 사용자 검토 대기.

## 왜

- 09-15 실거래 결과(비공개). 그날 신호 35건을 전부 샀어도 평균 −0.63%였다. 문제는 한도·순서가 아니라 **신호 자체**다.
- 복기에서 나온 가설: 장중 기사 진입(실거래 사례, 종목명 비공개), 이미 떨어지던 종목(기사 전 −2% 이하 13건 평균 −0.84%), 섹터 흐름(제약 +7.3% 날 제약 진입 0, 약세 섹터 금융·통신에 신호 집중).
- 지금까지 규칙은 6~7거래일로 골랐다. simnode `data/toss_history`에 2025-08~ 기사 17만 건(245종목에서 멈춤)과 같은 기간 분봉이 있다. **약 250거래일로 다시 고른다.**
- 머신러닝은 표본 대비 위험하다(기존 연구에서 릿지·GBM이 단순 규칙보다 못함). 사람이 정의한 규칙 후보를 **베이즈 최적화로 탐색하고, 베이즈 모형으로 판정**한다.

## 제1원칙: 백테스트 = 실매매 (운영 동일성)

사용자 지시(2026-09-15): **테스트와 매매는 무조건 같은 조건이어야 하고, 실매매에서 가능한 것만 테스트한다.**

이를 위해 규칙을 복사해 다시 짜지 않는다. **운영 코드를 그대로 돌리는 리플레이 엔진**을 만든다.

- 판정: `anthropic_client`의 운영 프롬프트 함수, 같은 모델(Haiku 4.5), 같은 입력(운영 v2는 `article.summary or content` — 과거 기사도 summary가 있으므로 동일 조건 가능).
- 신호: `SignalGenerator`, `entry_filter` 그대로.
- 주문·보유·청산: `AutoTrader` 그대로. 브로커만 `SimBroker`(분봉 기반)로 바꾼다. 시계는 주입된 가짜 시계.
- 한도: `TradingLimits` 그대로 (1주, 동시 5, 하루 10, 진입 09:00:30~14:30, TTL 5분, 15:00 청산·재시도, 노출 100만원, 추가매수 규칙).
- 비용: 매도세 0.20% + 수수료 편도 0.015%.

**운영에서 실시간으로 얻을 수 없는 정보를 쓰는 후보는 넣지 않는다.** 예: 섹터 흐름 필터는 운영 데몬이 장중에 섹터 수익률을 받을 수단(키움 업종 TR 등)을 먼저 확인하고, 없으면 후보에서 뺀다.

### 시뮬레이션이 운영과 달라지는 지점과 처리

| 항목 | 운영 | 리플레이 | 처리 |
|---|---|---|---|
| 기사 발견 시각 | Toss 대시보드 폴링 + 판정 지연 | 발행 시각 + 지연 | 운영 로그(09-14~)에서 발행→신호 저장 지연 분포를 재서 표본 추출. 분포는 매일 갱신 |
| 기사 모집단 | 대시보드에 뜬 기사 | 종목별 과거 뉴스(더 넓음) | 9월 겹치는 기간에 대시보드 기사(`news_articles`)와 종목별 기사를 대조해 **대시보드에 뜨는 기사를 가려내는 필터**(newsType·ticsTitles 등)를 정한다. 일치율을 문서에 남긴다 |
| 매수 체결 | 매도호가 지정가, 5분 TTL | 분봉 | 주문 분 다음 분봉 시가를 매도호가로 보고, TTL 5분 안에 저가 ≤ 지정가일 때만 체결. 상한가 잠김(고가=저가=상한가)은 미체결 |
| 매도 체결 | 매수호가 −할인, 1분 재시도 | 분봉 | 다음 분봉 시가 기준, 재시도 할인은 운영 코드가 계산 |
| 현금 | scalp-it과 공유 | 고정 | 운영 노출 한도(100만원)만 적용 |
| 종목 커버리지 | 전 종목 | 분봉 있는 종목 | 백필을 전 종목으로 재개. 분봉 없는 기사는 제외하고 제외율을 기록 |

## 단계

### 1단계: 프롬프트

- 표본: 탐색·선택 구간에서 월 × 섹터 × 세션(장전/장중/장후) 층화 1만 건. 선택된 프롬프트만 전체 기사로 확장.
- 후보: 운영 v2, v4(요약 입력판), 복기 가설을 반영한 신규 1~2종(예: 재료 지속성·섹터 테마 필드 추가). **LLM에는 사실 추출만, 점수 계산은 코드**(기존 연구의 v3 실패 원칙).
- 호출: Haiku 4.5, Batch API. 캐시 재사용(`data/eval/cache/`). **예산 상한 $80** — 넘을 것 같으면 멈추고 보고.
- 평가 지표: 각 프롬프트로 만든 신호를 운영 기본 정책(진입·청산 현행)으로 **리플레이한 하루 포트폴리오 손익**. 종가 대비 수익 같은 대리 지표로 고르지 않는다.

### 2단계: 신호·진입

선택된 프롬프트 고정, 청산은 현행 고정. 탐색 파라미터(모두 운영에서 계산 가능해야 함):
- 점수 하한, subject 허용(main/partial), persistence·material_type 제외 목록
- 세션별 진입 여부(장전/장중)
- 기사 전 움직임 상한(현행 +3%)과 **하한**(신규, 떨어지는 종목 제외)
- 배치 내 순위 기준(surprise, persistence, score)
- 섹터 흐름 필터 — 운영 데이터 소스 확인 시에만

### 3단계: 청산·추가매수

신호·진입 고정. VWAP 이탈(gap, 최소 이익), 손절(없음/2/3/5%), 청산 시각, 추가매수 조건.

### 4단계: 합동 확인

2·3단계 결과를 함께 켠 정책을 선택 구간에서 확인한 뒤, 보류 구간을 한 번 돌린다.

## 베이즈 방법

**탐색:** Optuna TPE, 탐색 구간에서만. 운영 정책을 첫 시도로 넣는다. 시도 수 단계당 ≤ 300.

**판정 모형:** 선택 구간의 거래일별 포트폴리오 손익 차이 d_t = (후보 − 운영 정책).
- d_t ~ Student-t(ν, μ + u_month, σ), u_month ~ Normal(0, τ), μ ~ Normal(0, 약한 사전 — 0 쪽으로 수축), 월 효과로 장세 차이를 분리.
- 구현: PyMC 또는 NumPyro(simnode), 수렴 진단(R-hat < 1.01).

**채택 조건 (모두 충족):**
1. P(μ > 0) ≥ 0.90
2. **손실 방지:** 하루 손익 하위 5% 평균(CVaR 5%)이 운영 정책보다 나쁘지 않을 사후확률 ≥ 0.80. "벌지 못하면 잃지 않는다"를 조건으로 넣는다.
3. 월별로 나눴을 때 선택 구간 4개월 중 3개월 이상 μ_month > 0
4. 보류 구간: 방향이 같을 것(크기는 요구하지 않음)

탈락하면 운영 정책을 유지한다.
