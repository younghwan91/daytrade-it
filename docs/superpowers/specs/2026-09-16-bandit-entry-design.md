# 최소 데이터 RL: 베이즈 컨텍스트 밴딧으로 진입 선택 — 설계

작성 2026-09-16. 사용자 지시(2026-09-16 00:03): "최소 데이터로 할 수 있는 RL을 구상해서 매매를 최적화하고 오늘 매매에 반영. 못 끝내면 매매를 쉰다."

## 왜 밴딧인가

- 표본은 거래일 7일, 판정 쌍 약 550개다. 순차 RL(보유 중 매 분 행동 선택)은 이 양으로 학습할 수 없다.
- 매매 결정의 핵심은 "이 신호를 살까, 사면 몇 순위로 살까"다. 이는 **컨텍스트 밴딧**(상황 → 행동 → 보상)으로 정확히 표현된다.
- 리플레이 엔진이 있으므로 **모든 행동의 보상을 반실사실(counterfactual)로 계산**할 수 있다. 각 신호를 샀다면 얼마였는지를 운영과 같은 조건으로 잰다. 탐색 비용 없이 전체 피드백을 받는 밴딧이라 데이터 효율이 가장 높다.
- **베이즈 선형 모형**(정규-역감마 켤레 사전)은 작은 표본에서 강한 수축으로 과신을 막고, 사후분포에서 "이 신호가 이익일 확률"을 바로 준다. 운영에서는 매일 새 데이터로 사후를 갱신한다. 이것이 온라인 강화학습 부분이다.

## 제1원칙 (0단계 스펙 계승)

- **백테스트 = 실매매.** 밴딧 판단 코드는 운영 코드(`application/trading/bandit.py`)이고 리플레이가 같은 코드를 부른다.
- **못 볼 건 학습하지 않는다.** 특징은 결정 시점에 운영이 계산할 수 있는 값만 쓴다. 보상은 그 신호 이후 가격이지만 라벨로만 쓰고 특징에는 넣지 않는다.
- LODO로 평가하고, 빠진 날에만 적용한 결과로 판정한다(`bayes_judge.judge`, 스펙 조건 1~3; 조건 4 전진 5일은 사용자 지시로 면제 — 결과 문서에 명시).

## 행동과 보상

- 결정 시점: 폴링 배치에서 선정 규칙(`SelectionConfig`)을 통과한 각 후보.
- 행동: `enter`(진입) / `skip`(건너뜀). 진입한 뒤의 청산·손절은 선택된 정책(`TradingLimits`)을 그대로 따른다.
- 보상 r = 그 후보를 1주 진입했을 때의 순손익률 = `net / 매수금액` (비용 포함, `trade_pnl` 기준). skip의 보상은 0.
- 반실사실 보상 계산: 동시 보유·일일 한도·노출·현금 한도를 풀어 둔 정책으로 하루를 리플레이하면, 1주 단위라 후보끼리 간섭 없이 모든 후보의 진입 결과가 나온다. 진입 타이밍 규칙이 켜진 정책이면 대기 중 만료된 후보의 보상은 0이다.

## 특징 (모두 결정 시점 운영 계산 가능)

| 이름 | 출처 |
|---|---|
| `score`, `surprise`, `specificity`, `sentiment_strength` | LLM 판정 (v2) |
| `persistence` (one_off/multi_quarter/structural 원핫), `subject_main` | LLM 판정 |
| `pre_entry_move` | 추격 금지 필터가 이미 계산 |
| `premarket` | `article_session` |
| `minutes_since_open` | 결정 시각 |
| `ret_5m` | 종목 완성 분봉 최근 5개 종가 수익률 (`get_minute_bars`, `ts < 현재 분`) |
| `mkt_move` | KODEX 200(069500) 현재가 / 전일 종가 − 1 (`get_quote` + 고정 전일 종가) |

- 표준화 평균·표준편차는 학습 데이터에서 계산해 모형 파일에 함께 저장한다.

## 모형

- r = xᵀw + ε, ε ~ N(0, σ²); 사전 w ~ N(0, σ²·λ⁻¹·I), σ² ~ InvGamma(a₀, b₀). 절편만 약한 사전.
- λ(수축 강도)는 LODO 안쪽에서 {1, 3, 10, 30, 100} 중 선택.
- 판단: 사후 예측분포에서 `p = P(r > 0)`, `m = E[r]`. `p ≥ min_prob` 이고 `m ≥ min_edge`면 진입 후보. 순위는 `m` 내림차순(`rank_key = "bandit"`).
- `min_prob` ∈ {0.5, 0.55, 0.6, 0.7}, `min_edge` ∈ {0, 0.002, 0.005}도 학습일 안에서 선택.
- 모형 파일(JSON): 특징 이름, 표준화 값, 사후 평균·공분산·a·b, λ, 임계값, 학습 날짜 목록.

## 운영 연결

- `SelectionConfig.bandit_model: str | None = None` (정책 파일 경로 기준 상대 경로). None이면 현행과 완전히 동일.
- 켜지면 `build_entry_candidate`가 특징을 만들고 판단한다. 거부 시 `news_entry: bandit skip`(p, m) 로그. 통과하면 `signal.metadata["bandit_m"]`, `["bandit_p"]`를 기록하고 `rank_batch(key="bandit")`가 m으로 정렬한다.
- 추가 브로커 호출(켜졌을 때만): 종목 분봉 1회, 069500 호가 1회.
- 매일 갱신(이 설계 범위에서는 수동): 장 마감 후 그날 리플레이 반실사실 보상으로 사후 갱신 → 모형 파일 교체.

## 평가와 채택

1. 반실사실 데이터셋 생성 (7일, simnode).
2. LODO: 학습 6일로 λ·임계값 선택·적합 → 빠진 날을 **한도가 켜진 실제 정책**으로 리플레이(밴딧 선택 + 순위) → 날짜별 순손익.
3. 비교 대상: (a) 운영 기본 정책, (b) 2·3단계 최적화 규칙 정책. `bayes_judge.judge`로 밴딧 정책 vs 둘 중 나은 쪽.
4. 채택: 조건 1~3 + 동일성 게이트 오류 0 + 날짜별 오류 0. 탈락이면 규칙 정책(채택 시) 또는 운영 기본값 유지.
